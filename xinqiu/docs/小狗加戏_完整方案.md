## 1. 现状与问题

### 1.1 狗现在只有两件事

| 行为 | 代码位置 | 现状 |
|---|---|---|
| 球面跟随 | `CompanionDog.cs` 45–62 `Follow()` | 目标点 = 玩家正后方 `dogFollowDistance = 1.8 m`，Slerp 贴球面，朝向 = `game.Player.forward` |
| 冷却叼回 | `CompanionDog.cs` 64–86 `Fetch()` | 半径 1.5/2.5/3.5 m，冷却 4/3/2 s；阶段一只叼塑料+有机，避开玩家准星目标；成功后 HUD 弹「狗 +1」 |

除此之外没有任何动作、姿态或入画设计。

### 1.2 为什么「调跟随距离」解决不了入画问题

第一人称相机（`PlayerCameraRig.cs` 48–52）眼高 1.62 m、垂直 FOV 72°，16:9 下水平半视角约 52°、垂直半视角 36°。狗体高约 0.47 m（中心离地约 0.235 m）。

- 狗在玩家**正后方**，方位角 180°，平视时永远在视锥外 → 无论 1.8 m 还是 3 m 都看不见。
- 要入画必须同时满足：**位于身前**、水平距离 ≥ 1.9 m（1.385 / tan36°）、水平偏角 < 52°。
- 取站位 **前 2.2 m / 右 0.9 m**：水平距离 2.38 m，俯角约 30°（在 36° 内），偏角约 22°（在 52° 内）→ 稳定出现在画面右下、准星之外。

**结论**：镜头存在感只能靠「周期性走到身前」实现，不能靠改 `dogFollowDistance`。

## 4. 详细设计

### 4.1 行为状态机（A 核心）

在 `CompanionDog` 内新增私有枚举与字段，不引入新组件、不改总入口：

| 状态 | 目标点 | 朝向 | 叼回 |
|---|---|---|---|
| `Follow`（默认） | 玩家正后方 1.8 m | `game.Player.forward` | 允许（原逻辑） |
| `Scout`（探路） | 玩家前方 2.2 m + 右侧 0.9 m | 到达后回望玩家 | **暂停**，避免前方狗突然叼走垃圾造成视觉跳变 |
| `Return` | 切回 Follow 目标点，用更慢的 Slerp 系数（2.5）自然回位 | 回望玩家 → 玩家 forward | 回位完成后恢复 |

**触发条件**（二选一，共用同一冷却）：

1. 距上次探路结束 ≥ `dogScoutInterval`（默认 18 s，范围 15–20）→ 自动进入 Scout。
2. 玩家静止 ≥ `dogScoutIdleTrigger`（默认 1.2 s）且冷却已到 → 进入 Scout，**一次静止只触发一次**（用 `bool idleTriggered` 防重复）。

**暂停语义**：沿用 `Update()` 现有的 `if (game.IsUiBlocking) return;`（第 38 行），打开任意面板时计时冻结，关面板后继续，不需要新按键或新仲裁。

**目标点计算**（放在 `Follow()` 内，替换现有 `back` 单向量）：

```csharp
Vector3 up = SphericalSurface.Up(player, center);
Vector3 fwd = Vector3.ProjectOnPlane(game.Player.forward, up).normalized;
Vector3 right = Vector3.Cross(up, fwd).normalized;   // Unity 左手系：up × forward = right
Vector3 offset = state == Scout
    ? fwd * cfg.DogScoutForward + right * cfg.DogScoutSide
    : -fwd * cfg.DogFollowDistance;
Vector3 anchor = SphericalSurface.Point(center, up, cfg.PlanetRadius, 0f);
Vector3 desired = SphericalSurface.MoveOnSurface(center, anchor,
    offset.normalized, offset.magnitude);
```

`SphericalSurface.Place()` 的 facing 参数：Follow 用 `game.Player.forward`；Scout / Return 用 `(player - transform.position)` 投影到切平面后的方向，形成「跑前面回头看你」。

### 4.2 动作表现 —— A（根物体级，零部件改动）

| 动作 | 实现 | 幅度上限 |
|---|---|---|
| 小跑起伏 | `animClock += dt`；`bob = sin(animClock * 2π * 4.5) * dogBobMeters`，加到 `Place()` 的离地高度参数 | ±0.01 m，停下时 lerp 归零 |
| 回望 | Scout 到位后 facing 由前向切到玩家方向，Slerp 0.25 s | 只改朝向 |
| 发现垃圾 | `Fetch()` 找到候选 `t` 后，facing 短暂 lerp 到 `t.transform.position` 方向 0.25 s；优先级：Scout / Return 回望 > 垃圾朝向 > 玩家 forward | 只改朝向 |
| 叼回前探 | `Fetch()` 成功分支设 `pulseTimer = 0.18 s`；`desired += fwd * dogFetchLunge * sin(π * t / 0.18)` | 0.12 m，一次回弹 |
| 停步等待 | 玩家速度 < 0.05 m/s 持续 0.6 s 后，bob 归零、探路判定生效 | 无位移突变 |

这些全部是根物体的 position / rotation 变化，`fixedColorRenderers` 与 `fixedMaterial` 一行不动。

### 4.3 动作表现 —— B（子部件级，默认不做）

**前置**：用户明确同意把 ART-012 从「固定外观」放宽到「允许局部动作」，并在冻结清单里登记（见第 6 节）。

**引用获取**：在 `CompanionDog.Init()` 里用 `transform.Find()` 缓存子物体引用，按 `WhiteboxBuilder.cs` 295–308 的现有命名：

```
Body / Head / Leg_0 / Leg_1 / Leg_2 / Leg_3 / Tail
```

无需改预制体绑定（`fixedColorRenderers` 已经包含这些 MeshRenderer，改它们的 `transform` 不影响材质）。

| 部件 | 动画 | 配置 | 上限 |
|---|---|---|---|
| Tail | `localRotation.z = sin(wagClock) * amp`；叼回成功时 amp 从基础值提到 boost，0.6 s 衰减 | `dogTailWagHz = 2.2`、`dogTailWagDeg = 14`、`dogTailBoostDeg = 26` | 30° |
| Leg_0..3 | `localRotation.x = sin(gaitClock + phase[i]) * dogLegGaitDeg`，对角相位 `[0, π, π, 0]`；频率随玩家速度 0 → 4.5 Hz | `dogLegGaitHz = 4.5`、`dogLegGaitDeg = 12` | 25° |
| Head | 垃圾朝向时 yaw 微调，叠加在 4.2 的根朝向之上 | `dogHeadLookDeg = 12` | 20° |

**约束**：只改 `localRotation` / `localPosition`；绝不写 `sharedMaterial` / `material` / `enabled`；A 已有 root bob，B **不再**给 Body 加 localPosition 起伏，避免双倍晃动；所有旋转后体高仍 ≤ 0.6 m。

### 4.4 配置字段（新增，默认值与钳制）

写在 `Assets/Scripts/Data/WhiteboxConfig.cs` 的「伙伴狗」Header 下（当前 103–108 行），并同步 `Assets/Data/WhiteboxConfig.asset`：

| 字段 | 默认 | 钳制范围 | 属于 |
|---|---|---|---|
| `dogScoutInterval` | 18f | 5–120 | A |
| `dogScoutHold` | 2.5f | 0.5–10 | A |
| `dogScoutForward` | 2.2f | 1.5–4 | A |
| `dogScoutSide` | 0.9f | 0.2–2 | A |
| `dogScoutIdleTrigger` | 1.2f | 0.3–10 | A |
| `dogBobMeters` | 0.01f | 0–0.03 | A |
| `dogFetchLunge` | 0.12f | 0–0.3 | A |
| `dogTailWagHz` | 2.2f | 0.1–8 | B |
| `dogTailWagDeg` | 14f | 0–30 | B |
| `dogTailBoostDeg` | 26f | 0–45 | B |
| `dogLegGaitHz` | 4.5f | 0.5–10 | B |
| `dogLegGaitDeg` | 12f | 0–25 | B |

## 8. 风险与降级

| 风险 | 处理 |
|---|---|
| 狗跑到身前挡住近处垃圾 | 站位固定**右侧** 0.9 m、体高压在 0.6 m 以下；必要时加「玩家准星命中近处垃圾时提前结束 Scout」的降级开关（默认关） |
| 球面快速转向时狗「甩尾」 | 沿用 `1 - exp(-3.5*dt)` 的 Slerp；Return 用更慢的 2.5 系数 |
| B 的部件动画在低模上显抖 | 幅度取保守值（14° / 12°），且腿动画只在移动时启用；美术不认可就直接砍 B，A 独立成立 |
| 旧 `.asset` 缺新字段导致值为 0 | `OnValidate()` 里逐字段兜底（见 4.4 注意事项），并在 L2 校验里检查 `dogScoutForward > 0` |
| 新增 confirmed ID 拉低 `@trace` 覆盖率 | 改 `.cs` 文件头时同步追加编号，L1 会直接报出来 |

**总降级策略**：把 `dogScoutInterval` 调到极大（如 120）即等于关闭探路，狗回到原来的纯跟随状态；B 的任何改动都不被 A 依赖。
