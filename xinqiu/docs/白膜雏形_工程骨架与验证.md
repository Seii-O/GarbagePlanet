│                     env_station_whitebox.prefab, env_landmark_whitebox.prefab
├─ Scenes/         WhiteboxPrototype.unity
├─ Whitebox_Spec_Notes.txt      （规格对照，供 @trace 扫描）
└─ _Game/          **保留**：工程原有的球面控制器 / 相机 Rig / 双手，白膜直接复用
docs/              design-freeze.json, project-spec.json, baseline-check.json,
                   unity-check-report.json, unity-compile-final.log,
                   whitebox-validate.json, whitebox-play-smoke.json, 本验证文档
Tools/             ensure_meta.py（离线补 .meta，零第三方依赖）

**为何没有 asmdef**：本轮累计 18 个脚本（<30），且 `Boot` 层要复用已存在于预定义程序集 `Assembly-CSharp` 的 `PlanetCleaner.PlayerController` / `PlayerCameraRig` / `FirstPersonHands`。加 asmdef 会让命名程序集无法引用预定义程序集，反而破坏编译。按架构文档「脚本少时先用目录分层」，本轮只做目录分层，`Editor/` 目录由 Unity 自动归编辑器程序集。这是与策划案 §12 的一处**明示偏差**，后续脚本量上来再拆分并同步改冻结清单。

| `sys_whitebox` | 所有系统组件挂同一根物体，`WhiteboxGame.Start()` 固定顺序 Init | Boot |

关键实现约定：

- **不手写场景/预制体 YAML**：全部由 `WhiteboxBuilder` 用 `AssetDatabase` / `PrefabUtility` / `EditorSceneManager` 生成；菜单或 `-executeMethod` 可随时重跑，GUID 稳定。
- **垃圾永不改色**：可交互时只打开独立的青色地标环子物体，垃圾本体材质不参与阶段插值。
- **狗不参与任何材质插值**：`CompanionDog.Init` 一次性写入固定材质；`EcoStage` 只接触地表/水两个 Renderer，没有 `UpdateLook`、没有阶段色数组。
- **数值不写死**：全部在 `WhiteboxConfig.asset`，`OnValidate` 做上下限钳制。待拍板项（C1–C7、C13）一律标 `[待拍板]` 并给建议默认值。
- **对象池**：`TrashSpawner` 按预制体分栈复用，地图上限 50 件，满则暂停生成。
- **存档**：`Application.persistentDataPath/trash_planet_whitebox_save.json`，原子写入 + version 字段 + 读失败回退。

### 3.1 Hierarchy 里的可编辑 UI 面板（本轮新增）

白膜 UI 原先是 `OnGUI` 运行时绘制，Hierarchy 里看不到、也改不了格式。现在整套面板是场景里的真实 uGUI GameObject：

```
UI_Whitebox   Canvas / CanvasScaler(1920×1080) / GraphicRaycaster
              + WhiteboxCanvasHud（内容驱动） + WhiteboxUiActions（按钮回调）
├─ Crosshair                 常驻准星（正式版唯一常驻 UI）
├─ BagWarning (CanvasGroup)  背包 >80% 呼吸边框，含 4 条细边
├─ DurabilityBar             大型垃圾耐久条（Background + DurabilityFill）
├─ FloatsRoot                拾取浮字容器
│  └─ Txt_FloatTemplate      浮字模板：改它就等于改所有浮字样式
├─ Hud_Debug                 F1 调试信息（Txt_Bag / Txt_Materials / Txt_Tool / Txt_Progress / Txt_Quest / Txt_Stats）
├─ Panel_Station             M 中转站（Btn_Deposit / Btn_Process_0..3 / Btn_Craft_0..2 /
│                            Btn_Upgrade / Btn_CloseStation / JobBar / Txt_Job）
├─ Panel_Pause               ESC 暂停（Btn_Resume / Btn_Restart / Btn_QuitPause）
├─ Panel_Settlement          结算（6 个 Txt_* / Btn_RestartSettlement / Btn_QuitSettlement）
├─ Txt_Hint / Txt_Notice / Txt_Deposit   常驻提示文字
└─ StageFlash                阶段白光（Canvas 最上层，alpha 由代码控制）
EventSystem   EventSystem + StandaloneInputModule
```

**怎么改格式**

- 在 Hierarchy 展开 `UI_Whitebox`，把 Scene 视图切到 2D（或直接选中对象在 Inspector 调 RectTransform）：锚点、位置、宽高、Image 颜色、Text 字体字号、按钮配色、面板层级都随你摆。
- 生成时 `Hud_Debug` 与 `Panel_Station` 是激活的，编辑器里能直接看到并调整；`Panel_Pause` / `Panel_Settlement` 默认灰显，点一下眼睛图标即可编辑。运行时四个面板的显隐由 `WhiteboxCanvasHud` 按状态接管，不会覆盖你在编辑态摆好的格式。
- **代码只写内容，不写格式**：运行时只改 `Text.text`、`Image.fillAmount`、`CanvasGroup.alpha`、`GameObject.SetActive`，不碰 RectTransform / 字体 / 颜色常量 / 层级。
- 按钮 OnClick 是 Inspector 里可见的持久化绑定，指向同一根物体上的 `WhiteboxUiActions`（`DepositAll` / `Process(int)` / `Craft(int)` / `UpgradeTool` / `CloseStation` / `Resume` / `Restart` / `Quit`）。想换成自己的脚本，直接改绑即可。
- 中文字体：uGUI 内置字体不含中文字形，`WhiteboxCanvasHud.AutoFixCjkFont` 在 Play 时自动回退到本机中文字体（微软雅黑 / 黑体等）；如果你自己在 Inspector 指定了字体资产，关掉该开关就不会被替换。编辑器里看到方块字属正常，Play 后正常显示。

**不覆盖你的改动 / 不破坏人物**

- 菜单 `Tools/垃圾星球白膜/④ 生成 / 补齐 Hierarchy UI` 是幂等的：`UI_Whitebox` 已存在时只补「空引用 / 缺失组件 / 空按钮绑定」，绝不重建对象、不改你调过的布局与配色。
- 想彻底恢复默认布局：删掉 `UI_Whitebox` 再点 ④ 即可，其它场景物体、玩家、双手都不动。
- 事件系统用 `StandaloneInputModule`，因为工程 `ProjectSettings.asset` 的 `activeInputHandler: 0`（旧 Input Manager），与第一人称 Rig 一致；没有引入新 Input System。所有非按钮 Image 的 `raycastTarget` 均为 false，不会挡住准星拾取。
- **玩家含双手且保持原样**：`Main Camera/Hands` 下的 `HandLeft` / `HandRight` 与 `FirstPersonHands` 组件未被改动；校验器新增一条专门检查它们仍在。
- IMGUI 版 `WhiteboxHud` 保留为「代理 + 回退」：绑定 uGUI 后不再画 IMGUI（不会出现两层面板）；解绑或勾选 `forceImGui` 可随时回到纯 IMGUI。

## 4. 怎么玩（Play 模式手测清单）

编辑器里打开 `Assets/Scenes/WhiteboxPrototype.unity`（命令 `Tools/垃圾星球白膜/② 打开白膜场景`），按 **Play**：

| 键 | 行为 |
|---|---|
| WASD / Shift | 球面切平面移动（Shift 由既有 Rig 处理） |
| 鼠标 | 第一人称视角，进入 Play 自动锁定光标 |
| 左键 | 准星命中 → 拾取普通垃圾 / 拆解大型垃圾（耐久条） |
| M | 距中转站 14 m 内打开 2D 经营面板；再按 M 关闭 |
| ESC | 关闭面板或暂停（后台加工/制造计时一并冻结，C10 默认） |
| F1 | 开关白膜调试信息（正式版常驻 UI 只有准星） |
| F5 / F9 | 新的一局 / 手动存档 |

逐项验收（对应策划案 M2/M3/M4）：

1. 绕球面走到背面：不穿地、相机随法线旋转、地平线弧始终可见。
2. 对准青色描边的垃圾左键拾取，出现 `+1`；背包满时目标不消失、提示「背包已满」。
3. 对准大型垃圾连续点击，耐久条递减到 0 后回池，产出进入背包。
4. 看身后 1.2–2.5 m：狗始终跟随，冷却到点会叼回玩家准星**没指着**的普通垃圾。
5. 走回中转站按 M：投放 → 加工四类 → 制造再生建材板（中转站解锁）→ 造肥料包/过滤器 → 土地/水源进度上涨。
6. 进度跨过 30% / 70%：地表、水、天空、雾、主光角度一起平滑变化并闪一次白光；**对比三阶段截图，狗的固有色始终是 `#D8C3A0`，无斑块、无姿态差异**。
7. 走完十步任务链出现 6 项结算面板；**确认结算时自动解锁光标、3D 输入冻结，面板按钮可点**；点「重开一局」回到污染阶段；F9 存档后退出重进，数值读回一致。

> 白膜演示把刷新间隔乘了 `WhiteboxSpawnTimeScale = 0.25`（15/12/10 s → 3.75/3/2.5 s），只为缩短验证时间；**这不是冻结数值**，正式验证请把它调回 1。

## 5. 可复现验证方式（四层，从轻到重）

所有命令都在**工程根目录**执行；`<Unity>` 指本机 Unity 2022.3.62f3c1 的 `Editor/Unity.exe`，不要写进仓库。

### L1 · 离线工程自检（不需打开编辑器）

```bash
python <技能包>/scripts/check_unity_project.py . \
  --spec docs/project-spec.json \
  --freeze docs/design-freeze.json \
  --compile-log docs/unity-compile-final.log \
  --json docs/unity-check-report.json
```

退出码 0 = 通过。检查项覆盖目录、版本、包清单、`.meta` 配对、GUID 唯一、场景↔构建列表双向一致、C# 括号/字面量、悬空 GUID、机器绝对路径、`@trace` 覆盖率、真实编译日志。

### L2 · 编辑器内一键校验

菜单 `Tools/垃圾星球白膜/③ 校验白膜工程`，结果落盘 `docs/whitebox-validate.json`。校验内容：配置 / 10 个预制体 / 场景 / 构建列表存在、场景无缺失脚本、`WhiteboxGame` 装配引用齐全、7 个垃圾预制体引用无空项、狗固定色号与配置一致；**新增 13 项**覆盖 Hierarchy UI 根 / Canvas / CanvasScaler / GraphicRaycaster / `WhiteboxCanvasHud` 引用 / `WhiteboxUiActions` / 4 个面板可见 / 15 个按钮持久化绑定 / EventSystem + StandaloneInputModule / IMGUI 代理绑定 / 玩家双手保留。退出码由批处理入口显式给出。

相关菜单：`④ 生成 / 补齐 Hierarchy UI`（幂等，只补空引用，不覆盖布局）、`⑤ 重跑 Play 冒烟测试`。

### L2.5 · Play 冒烟测试（编辑器内，一次性）

`WhiteboxPlaySmoke` 自动打开白膜场景、进 Play 约 3 秒、收集 `LogType.Error/Exception/Assert`、退出 Play 并把结果写到 `docs/whitebox-play-smoke.json`。复验触发条件：报告不存在 / 报告比场景旧 / 报告里 `pass: false`（下一次域重载自动复验一次），或直接点菜单 `⑤ 重跑 Play 冒烟测试`。当前场景有未保存改动时会先落盘再跑，不弹保存框。
注意：报告里的 `frames` 是**编辑器 update 回调**计数，域重载后重新计数，不是游戏帧数；启动是否真的跑完，以 Editor.log 中 `[WhiteboxGame] 启动完成` 等带标签日志为准。

### L3 · 命令行重建与校验（**必须先关闭 Unity 编辑器**，同一工程不能双开）

```bash
"<Unity>" -batchmode -quit -nographics \
  -projectPath . \
  -executeMethod TrashPlanet.Whitebox.Editor.WhiteboxBuilder.BuildAllBatch \
  -logFile Logs/whitebox-build.log

"<Unity>" -batchmode -quit -nographics \
  -projectPath . \
  -executeMethod TrashPlanet.Whitebox.Editor.WhiteboxValidator.ValidateBatch \
  -logFile Logs/whitebox-validate.log
```

两个入口都用 `EditorApplication.Exit(0/1)` 显式给退出码；`-nographics` 下不给渲染结论。重建是幂等的（同路径覆盖、GUID 不变），但会重置场景内容，别在有未提交场景改动时跑。

### L4 · Play 模式取证

按第 4 节清单录屏；重点留三类证据：球体背面位置日志、三阶段色板取样、狗固有色取样。帧率/内存/包体/手感仍为 `[待实测]`，未测前不写「已平衡」。

## 13. 描边收窄 + 立体感增强（22:43）

用户反馈两点：① 白描边太粗，要收窄到当前的三分之二、更纤细；② 物体整体偏扁平，要更清晰的三维纵深与体积感。

改动（仍坚持：只动垃圾预制体资产 / 材质资产 / 场景光照设置，**不触发整体重建**——那会清掉 Hierarchy 里用户正在改的 UI 面板，也**不碰第一人称双手**）：

- **描边收窄**：放大系数 `1.10f` → `1.06667f`（即 `ThinOutlineScale` 常量；比物体大 6.667%，为原宽度 10% 的三分之二）。`CreateTrashPrefabs` 与 `RefreshTrashOutlines` 两处统一改用该常量；`OutlineNeedsRefresh()` 检测现有预制体是否已是新宽度。编译后自动修复（Key 升到 v2）对 7 个预制体重刷，实测 `Outline/Body` 缩放比 = 1.0667，确认生效。
- **立体感光照**（核心去扁平手段）：原来环境光偏高（`ambientLight=0.55`）把明暗梯度洗平了。现在
  - `BuildSceneContents` 与菜单 **⑦ 增强立体感光照（当前场景）** 把环境光压低到 `0.30`；
  - 主光之外新增两盏**无阴影**方向光：`env_fill_light`（冷色、主光对侧 150°，强度 0.55，柔化暗部但不抹平梯度）+ `env_rim_light`（暖白、背后上方 55°/210°，强度 0.40，勾勒边缘 → 纵深与体积）；
  - `WhiteboxGame.Start()` 运行时也兜底把 `ambientLight` 设为 `0.30`，保证无论场景设置如何、Play 里都有清晰的明暗梯度。
  - 两盏补光都不被 `EcoStage` 接管（`EcoStage` 只转主光角度与地表/水/天空/雾），阶段切换不会动它们。
- **材质高光**：垃圾 / 狗 / 中转站 / 锈 / 地标 / 地面等 Lit 材质的 `smoothness` 整体上调（如垃圾 `0.08→0.28`、狗 `0.20→0.35`），让方向光在曲面上扫出可见高光，进一步读出体积。该值在 `RefreshTrashOutlines` 走 `CreateMaterials()` 时已一并回写现有材质资产。

怎么调：
- **描边粗细**：改 `WhiteboxBuilder.ThinOutlineScale`（越大越粗），再点菜单 ⑥ 或等自动修复重刷。
- **立体感强弱**：直接调 `BuildSceneContents` 里的环境光值，或点菜单 ⑦ 重新应用到当前场景；也可单独微调 `env_fill_light` / `env_rim_light` 的强度与角度（在 Hierarchy 的 `WorldRoot` 下，可随意拖改，属场景物体不属于脚本生成约束）。

验证：离线自检 0 错误 / 1 警告（唯一警告仍是 ART-006、NUM-011 真实未做的覆盖缺口）；最终编译摘录 0 编译错误、自动收窄 7 个描边、自动应用 1 次立体感光照；场景已保存（含新增两盏灯），UI 面板与双手未动。
