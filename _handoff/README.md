# _handoff — 记忆中枢

**这是唯一固定不变的存档点。** 所有会话（不管开在哪个 `E:\workbody\日期-时间\` 工作区）都往这里写，第二天新会话先读这里。

## 里面有四个东西

| 文件 | 作用 | 谁写 |
|---|---|---|
| `项目总账.md` | 长期有效的事实：工程坐标、硬约束、环境坑、**决策台账（当前生效版）** | 人工/我，重要变更时改 |
| `明日开工.md` | 只有一份，每天覆盖。第二天读它 30 秒就能接上活 | 定时任务 + 收工口令 |
| `日报/YYYY-MM-DD.md` | 当天的详细记录：改了什么文件、为什么、验证到哪一步 | 定时任务 + 收工口令 |
| `README.md` | 本文件 | — |

## 三条写入规则

1. **决策只认总账。** 聊天里反复翻烙饼的（比如中转站四页签/五页签）不进日报结论，只在 `项目总账.md` 的决策台账里保留"当前生效"一行，冲突时以 git HEAD 代码为准。
2. **日报写三件事就够**：定了什么 / 改了哪些文件 / 明天第一步。不要复述过程。
3. **不写没验证的东西当结论。** 没编译过就写"待验证"，不要写"已修复"。

## 第二天怎么用

- 新会话第一句：`读 _handoff\明日开工.md 和 项目总账.md，接着干`
- 或直接说：`接着昨天的活` —— 我会自己去读。

## 为什么不用工作区自带记忆

`E:\workbody\<时间戳>\` 每个任务一个新目录，`.workbuddy/memory` 跟着目录走，所以 2026-11-14 到 11-25 攒了 18 份互不相通的日志。工作区记忆继续写（细节多、有行号），但**汇合点**必须是这个目录。
