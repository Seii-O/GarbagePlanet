### C. 主题重新落点（第 1、2 章改动）

- **v1.1**：陪伴靠「同步变化」表达——星球变干净，狗也变干净。
- **v1.2**：陪伴靠「**恒定**」表达——地表、水、天空、雾、光照三阶段全都在变，唯独身边这条狗从头到尾是同一个样子、同一段步态、同一声轻吠。玩家每抬头对比一次，都会重新确认「还有一个没被这颗星球改变的生命一直跟着我」。
- 收益：① 主题更锋利，环境成为唯一变量；② 省掉一整套角色状态资源与插值逻辑，比赛工期更稳；③ 避免「把伙伴也当进度条」的观感，减少把角色物化的争议。
- 差异点：不靠对话、好感度、外观阶段、常驻 UI 表达陪伴，只用**位置与行为**表达（它总在你身后 1.2–2.5 m、总在你没瞄的地方叼回东西）。

### F. 关键冲突：狗 vs 工具 Lv.3 自动吸附（C11 仍待拍板）

改前 Lv.3「自动吸附普通垃圾」是唯一被动收集能力；狗加入后两者重叠，Lv.3 会失去意义。**建议把两条成长线拆开**：

| 成长线       | 来源               | 管什么                                         |
| --------- | ---------------- | ------------------------------------------- |
| 工具 Lv.1→3 | 玩家花材料升级          | 玩家**主动**效率：拾取 2/3/4 m、拆解 1→2、Lv.3 无冷却即时范围吸附 |
| 狗         | **生态修复进度**（不花材料） | 伙伴**被动**效率：有冷却、有类型限制、随生态提升半径与频率（**外观不变**）   |

Lv.3 是「站定即收」，狗是「跑过去叼」，且狗只处理玩家准星未指向的目标。**环境越好，同行者越有力，但它看起来始终是同一条狗**，正好扣题。此项需用户拍板（C11）。

## 1. 一句话定位 `[原文]` + `[补充·待确认]`

> **v1.2**：你是一名星球环保管理员，带着一条狗，站在一眼能看完的小星球上，把废弃物一件件捡回中转站、加工成环保产品；地表、水、天空和光都在一点点变好，**只有它从头到尾是同一个样子、同一段步态**。你修的是星球，陪你走的是它。**每抬一次头，都看见自己正站在一个球上，而身边一直是它。**

体验目标是「看得见的修复进度 + 有人同行」，不是战斗、不是生存压力；比赛命题「同行」由这条狗承载，不靠对话与剧情，**也不靠外观变化**——环境是唯一变量，狗是唯一常量。`[v1.2]` + `[分析]`

## 5. 核心循环 `[原文]` + `[补充·待确认]`

### 5.1 三层循环

| 层级        | 时间尺度              | 环节与耗时                                                                            | 流失点                | 对策                                            |
| --------- | ----------------- | -------------------------------------------------------------------------------- | ------------------ | --------------------------------------------- |
| 微循环（秒级）   | 0.25–3 s          | 准星对准 → 描边亮起（≤0.2 s）→ 左键 → 物件吸附/耐久条变化 → +1 飘字（0.25 s）                             | 反馈延迟 > 0.2 s 会「发木」 | 反馈全部走即时通道，动画时长按美术案固定值（见 9.5）                  |
| 单局循环（分钟级） | 14–19 min `[待实测]` | 探索 → 拾取 → 返回中转站（往返约 6 s `[待实测]`）→ 存入 → 加工（2.5 s/次）→ 制造（5/8/12 s）→ 修复（+10%/件）→ 回到探索 | 背包满载后仍在外场游荡        | 80% 容量时 HUD 边框呼吸 `#E2603C`；满载即时提示，不吞掉垃圾模型     |
| 长线循环（小时级） | 跨多局               | 工具 Lv.1→2→3 → 拾取/吸附范围扩大 → 自动吸附解锁 → 生态阶段 I→II→III → 刷新变快 + 环保宣传减量 → 继续循环          | 阶段升级后看不到变化         | 主光角度 25°→45°→60° 平滑插值 + 全屏白光 2.5 s；「太阳升起来」即叙事 |

### 5.3 决策密度检查 `[补充·待确认]`

单局循环中每 10 秒的「有意义选择」统计：探索期约 2–3 次（去哪、捡哪类、是否返回）、中转站期约 1–2 次（加工哪类、造什么、升不升级）。**连续 30 秒无选择** 的风险出现在「等待加工/制造 5–12 s」与「等刷新」；对策：加工与制造期间允许关闭面板回到 3D 场景继续拾取，进度在后台走。**每秒 > 1 次选择持续 30 s** 的风险出现在 Lv.3 自动吸附开启后；对策：自动吸附不产生点击决策，只保留移动决策。

## 7. 关卡与流程结构

### 7.1 球面场景分区 `[原文]`

球面按经度划 4 个区块，对应 4 类垃圾高密度区；区块之间用**低矮山脊**天然分隔但不阻断步行；每区中心一个视觉地标（枯树 / 倒塌广告牌 / 水塘），**玩家靠地标而非小地图定位**。

| 区块 | 主垃圾 | 地标 | 备注 |
|---|---|---|---|
| 东经区 | 塑料 | 枯树 | 高度不得超过视线水平线 `[原文·红线]` |
| 南经区 | 金属 | 倒塌广告牌 | 同上 |
| 西经区 | 有机 | 水塘 | 同上，兼作污染水域表现 |
| 北经区 | 电子 | 中转站（唯一建筑） | 唯一安全区、唯一暖色光源 |

> **红线**：任何垃圾堆、树、建筑高度不得超过视线水平线；不做远景假山、不做远景雾墙遮丑；地平线弧必须始终可见。

### 8.2 公式与极值验算

| 编号 | 公式 | 变量 / 单位 / 取值范围 | 极值验算结果 |
|---|---|---|---|
| NUM-001 | `collected = min(batch, capacityLeft[cat])` | batch=1 件；capacityLeft 0–10 件 | 最小 `(0,1)→0`（不消失、提示满载）；最大 `(10,1)→1` |
| NUM-002 | `materialOut = floor(garbageIn × convRate[cat])` | garbageIn 1–50 件；`convRate` 塑料/金属/电子 0.5、有机 1.0 `[推断]` | 全最小 `(1,0.5)→0` ⚠ 会白扣原料；全最大 `(50,1.0)→50`；`(50,0.5)→25`。**必须钳制最小加工批量 = ceil(1/convRate) = 2 件（普通）/ 1 件（有机）** |
| NUM-003 | `durability = max(0, D0 − clicks × dmg)` | D0 ∈ {5,8,10} 点；dmg ∈ {1,2} 点；clicks ≥ 0 | `(5,1,0)→5`；`(5,1,5)→0`；`(5,2,3)→max(0,−1)=0`；`(10,1,20)→0`。负值钳制生效 |
| NUM-004 | `progress = min(1.0, items × 0.10)` | items ≥ 0 个；0.10 = 每件 +10% `[原文]` | `(0)→0`；`(3)→0.30`；`(10)→1.00`；`(12)→1.00`（溢出钳制） |
| NUM-005 | `d = sqrt(2 × R × h_eye)`，`T_round = 2πR / v` | R 球体半径 m；h_eye ≈ 1.6 m `[补充]`；v ∈ {5,7} 单位/s `[原文]` | R=100 → d=17.89 m，绕行 125.7 s；R=200 → 25.30 m / 251.3 s；R=500 → 40.00 m / 628.3 s |

> **R 的可复算意义**：R=500 m 时球面视距恰为 40 m，等于美术案污染阶段雾能见度 40 m；R=100 m 时绕行一圈约 2 分钟，更贴合「一眼能看完的球」。**R 取值待实测/待拍板（16.1 C6）**，工程期把 R 做成可配置参数，不写死在代码里。

| 数据驱动 | 数值表（垃圾类型、配方、升级消耗、刷新间隔、色板）放 ScriptableObject 或 JSON，代码不写死数值 |
| 存档 | JSON 单文件，路径 `Application.persistentDataPath`（以官方文档当前版本为准） |
| 目录规范 | `Assets/Scripts/{Core,Gameplay,Station,Environment,UI,Editor}` · `Assets/Data` · `Assets/Art/{Models,Materials,UI,FX,Audio}` · `Assets/Scenes` · `docs/` |
| 程序集 | 按 Core / Gameplay / Station / Editor 划分 asmdef，Editor 程序集只在编辑器下编译 |
| 对象池 | 垃圾 50 件上限，全部走对象池，避免运行时频繁 Instantiate |
| 版本与证据 | 工程自检脚本输出 JSON 报告；未跑编译/自检的代码不得标「已完成」 |
